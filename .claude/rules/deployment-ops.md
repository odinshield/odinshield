# Production deployment & runtime ops

**Topology:** `compose.deploy.yaml` is the canonical standalone production stack — `php` + `worker` (both the `odinshield:${ODINSHIELD_IMAGE_TAG}` image) + `database` (postgres). TLS is terminated by an **external Traefik** instance on the shared `traefik` network (`docker network create traefik` once); FrankenPHP runs HTTP-only (`SERVER_NAME: ":80"`) and never does ACME. Operators copy `.env.deploy.example` → `.env`, fill it, then `docker compose -f compose.deploy.yaml up -d`. (Dev uses `compose.yaml` + auto-merged `compose.override.yaml`; a locally built image is smoke-tested with `make build-local` on the host.)

**Several instances on one Traefik:** the Traefik router, service and middleware names are keyed by **`INSTANCE_NAME`** (default `odinshield`, i.e. the historical name — a single-instance deployment needs no new variable). Those names are **Traefik-global, not stack-local**: two stacks that both call their router `odinshield` collide and one of them silently disappears, with no error anywhere — one host simply stops being routed. Everything else in the file is already multi-instance-safe by construction (no `container_name`, no `name:` on the volume, no `ports:`) — do not add any of those. **The labels are in list syntax on purpose:** Compose interpolates variables in label *values* only, never in label *keys*, so `${INSTANCE_NAME}` inside a mapping key would reach Traefik verbatim (measured: `config` emits the key as `$${INSTANCE_NAME:-odinshield}` while the value on the same line resolves). In list form the whole `key=value` string is one value.

**`compose.frontproxy.yaml`** is the override for deployments where **Traefik does not terminate TLS** because a reverse proxy in front of it does: `docker compose -f compose.deploy.yaml -f compose.frontproxy.yaml up -d` (both files on *every* compose call, including `logs` and `down`). It replaces the whole label block via the `!override` tag — a normal merge can overwrite or add label keys but never remove one, and removing `tls.certresolver` is the entire point: without a resolver in Traefik's static config that label makes it retry ACME forever. It also drops the HTTP→HTTPS redirect router (the front proxy answers port 80 itself, so Traefik's `web` entrypoint never sees those requests), makes **`TRAEFIK_MIDDLEWARES` mandatory** (fail-fast: an empty middleware chain is not a meaningful state when the app is exposed through a proxy chain), and switches the access log to a file under `${ODINSHIELD_LOG_DIR:-./data/log}`.

**Required env** (`.env`): `TRAEFIK_HOST`, `APP_SECRET` (`openssl rand -hex 32`), `POSTGRES_PASSWORD`, `MONOLOG_ERROR_TO`, and a pinned `ODINSHIELD_IMAGE_TAG` (avoid `latest`). Compose enforces these via `${VAR:?…}` — startup fails fast if unset. `MAILER_DSN` defaults to `null://null` (mail disabled). `.env.deploy.example` documents every option (CSAF schedule, FrankenPHP tuning, CrowdSec access logs). Two more, both optional in the base file: **`INSTANCE_NAME`** (see above; lowercase letters, digits and hyphen only — anything else is not a valid Traefik router name) and **`TRAEFIK_MIDDLEWARES`**, which the base file ignores entirely and `compose.frontproxy.yaml` requires. **Image tags carry no leading `v`**: the git tag is `v2.1.0`, the image is `2.1.0` (the Makefile tags from `VERSION` verbatim) — `ODINSHIELD_IMAGE_TAG=v2.1.0` fails the pull with `manifest unknown`.

**Two-proxy topology (first-line proxy in front of Traefik).** When something else terminates the public hostname and forwards to Traefik — e.g. an external Caddy on `demo.example.com` proxying to `internal.example.net` — three settings that look interchangeable must hold *different* values. Getting this wrong produces a 400 or a 404 with no useful error anywhere:

- `TRAEFIK_HOST` = **the host Traefik actually receives**. If the front proxy rewrites `Host` to the internal name, this is the *internal* name. Set it to the public name and Traefik's `Host(…)` rule matches nothing → Traefik's own bare-text `404 page not found`, and the request never reaches PHP.
- `TRUSTED_HOSTS_REGEX` = must list **the public name**. With `TRUSTED_PROXIES: REMOTE_ADDR` the immediate peer is trusted, so Symfony prefers **`X-Forwarded-Host`** over `Host` — and the front proxy puts the public name there even when it rewrote `Host`. Missing it → Symfony 400 (SEC-003), *with* app headers (CSP, Permissions-Policy) on the response.
- `APP_PUBLIC_URL` = the public base URL, or mail links from the worker point at a host outsiders cannot resolve.
- `TRUSTED_PROXIES` = **Traefik subnet + front-proxy IP** (#199, e.g. `172.22.0.0/16,10.20.0.2`). Symfony takes the right-most `X-Forwarded-For` entry it does not trust as the client; with the default `REMOTE_ADDR` that is the front proxy → every user shares one IP (measured on Demo 2026-10-19: the audit held only the front proxy's address), login throttling locks out everyone at once. Traefik must trust the front proxy as well (`forwardedHeaders.trustedIPs`), visible as `"<client>, <front proxy>"` in the access log. Caddy's `client_ip` in that log is **not** Symfony's view (Caddy trusts `private_ranges` and reads left-most) — check the `ip` column of any `*_audit` table instead. `REMOTE_ADDR` is resolved once per worker, on its first request — another reason to list addresses.

Since `TRAEFIK_HOST` feeds both the router rule and the derived trusted-hosts default, **no single value satisfies both** — hence the explicit `TRUSTED_HOSTS_REGEX` override.

These three settings are about the *application*; when that front proxy also terminates TLS, the *routing* needs `compose.frontproxy.yaml` on top (see Topology). The two are independent: a front proxy that merely forwards HTTPS to a Traefik holding its own certificates needs only the three settings above.

**Telling the two failures apart:** a 400 carrying `Content-Security-Policy`/`Permissions-Policy` came from Symfony; a bare `text/plain` `404 page not found` with no app headers came from Traefik (no matching router) — not from the app. The decisive evidence is Caddy's access log, which logs `host` and `X-Forwarded-Host` side by side; enable it via `CADDY_SERVER_LOG_OPTIONS` (see `compose.deploy.yaml`). Note the log then goes to the **file**, so an empty `docker compose logs php` no longer proves that no requests arrived. The bind-mounted log dir must be owned by **UID 33 (`www-data`)** — the prod image runs as `www-data`, not UID 1000.

**Startup is self-migrating:** `frankenphp/docker-entrypoint.sh` runs `doctrine:migrations:migrate --all-or-nothing` + `messenger:setup-transports` on `php` container boot (skipped when `SKIP_MIGRATIONS` is set — the `worker` sets it so only `php` migrates; the worker also `depends_on` `php` being healthy). First boot can take 60–90 s; the healthcheck `start_period` is 120 s. Upgrades are therefore just: bump `ODINSHIELD_IMAGE_TAG`, `pull`, `up -d`.

**Worker consume list is load-bearing:** the deploy worker runs `messenger:consume async scheduler_default scheduler_csaf scheduler_exploitation …`. The three `scheduler_*` transports are the Symfony Scheduler tick sources (`src/Schedule.php`, `src/Scheduler/CsafImportSchedule.php`, `src/Scheduler/ExploitationEnrichmentSchedule.php`) — drop one and its `RecurringMessage`s (CSAF import, EPSS/KEV enrichment) silently never fire even though `debug:scheduler` lists them.

**URL generation off the request:** mail links and other CLI/worker/async-generated URLs come from `DEFAULT_URI` (`APP_PUBLIC_URL`, falling back to `https://${TRAEFIK_HOST}`). The worker **must** have it set because `MailNotifier` runs in the async handler with no originating request. Behind Traefik, `TRUSTED_PROXIES: REMOTE_ADDR` + the Caddy `trusted_proxies`/`client_ip_headers` global options recover the real client IP (otherwise CrowdSec would ban Traefik).

**Data & first user:** Postgres persists in the `database_data` named volume (`docker compose down -v` destroys it). Back up with `pg_dump`. Seed the first admin with `odinshield:user:add … --admin` (login is by username, not email).

**Async processing:** Messenger with Doctrine transport (`doctrine://default?auto_setup=0`). Create the transport table once with `docker compose exec php bin/console messenger:setup-transports`. The dev stack runs a dedicated `worker` container that continuously consumes the `async` transport (`messenger:consume async --time-limit=3600`, recycles hourly) — no manual consume needed in normal development. For ad-hoc consumption use `make messenger-consume` (runs `messenger:consume --all` until interrupted).

**Worker network access in deploy:** `compose.deploy.yaml` puts the `worker` on **both** the `internal` (DB-only) and `traefik` networks. The `internal` network has `internal: true` set, which forbids outbound traffic — without the second network, the worker can't reach external SMTP for `SendEmailMessage`, NVD/MITRE CVE feeds, or any other outbound service. Traefik does not route HTTP to the worker because no `traefik.enable: true` label is set; the membership is egress-only. If you ever rip the `traefik` network off the worker, mailer-async will silently fail with `getaddrinfo: Temporary failure in name resolution` and queued messages pile up in the failure transport. The `php` container has both networks for the same reason (its requests trigger outbound mail dispatch via the messenger queue, fed by the worker).

**Path MTU in clouds (issue #107):** some clouds run their private network below the Ethernet default of 1500 — Hetzner Cloud uses **1450** — while Docker still creates its networks with 1500. The mismatch is silent and selective: small responses pass, large ones hang, so an importer times out against one provider (a TLS handshake with a multi-kilobyte certificate chain is enough) while everything else looks healthy. It belongs in the **host's** `/etc/docker/daemon.json` (`default-network-opts.bridge.com.docker.network.driver.mtu`), not in compose — it is a property of the environment, not of the application — and it only affects **newly created** networks, so an existing external `traefik` network keeps its MTU until it is removed and created again. A `driver_opts` entry in compose is useless for a network declared `external: true`.

**Docker:** PostgreSQL with a named volume (`database_data`) mounted at `/var/lib/postgresql` for persistent data (Postgres 18 uses `PGDATA=/var/lib/postgresql/18/docker`). Managed by Docker; survives `docker compose down` but is removed by `docker compose down -v`.

**FrankenPHP worker mode:** the `php` container runs Symfony in worker mode via the **native** `Symfony\Component\Runtime\SymfonyRuntime` (the default — no `APP_RUNTIME` override). It auto-selects `FrankenPhpWorkerRunner` when `$_SERVER['FRANKENPHP_WORKER']` is set by the Caddyfile `worker { file ./public/index.php }` block, reads `FRANKENPHP_LOOP_MAX` (default 500) for recycling, and additionally supports `FRANKENPHP_RESET_KERNEL`. (Historically a vendored `App\Runtime\FrankenPhpSymfony\Runtime` was used because `runtime/frankenphp-symfony` never accepted Symfony 8; `symfony/runtime` 8.1 ships the runner natively, so the vendored copy was removed.) The kernel is booted **once per worker**, so any service holding mutable instance state will leak across requests. Defenses:

- Implement `Symfony\Contracts\Service\ResetInterface` on any new stateful service — `services.yaml` autoconfigure auto-tags `kernel.reset` (see `EffectiveRiskListener` for the pattern).
- Don't memoise per-user data on Twig extensions / repositories — use a Twig variable in the template instead (see prior `NotificationExtension::$cachedCount` removal).
- Workers recycle every `FRANKENPHP_LOOP_MAX` requests (default 500, prod compose sets 1000) to bound memory growth.

**Postgres restart recovery:** Doctrine DBAL 4 has no `auto_reconnect`. After a `database` container restart, all live worker connections fail with `Doctrine\DBAL\Exception\ConnectionLost` and 500 every request until the worker recycles (up to `FRANKENPHP_LOOP_MAX` failures). Mitigation: **always restart `php` and `worker` immediately after restarting `database`** — `docker compose restart php worker`. A reconnect middleware is the proper fix; not added until measured pain.
